## 结果分析与结论

1. **加速比随着数据集规模增长而显著放大 (Scaling Efficiency)**：
   - **极小数据集 (min)**：MassFlow 相比 pyM2aia 获得了 **1.67x ~ 1.91x** 的加速。
   - **中型数据集 (mid)**：加速比进一步扩大到 **2.47x ~ 3.49x**。
   - **较大数据集 (example)**：平滑滤波加速比上升到 **3.57x ~ 3.66x**，归一化保持在 **1.67x ~ 1.73x** 的稳定加速。
   - **大型数据集 (original)**：加速比达到峰值，高斯平滑加速达 **4.15x**，归一化加速达 **3.31x ~ 3.48x**。
   - **分析**：在较小的数据集（如 `min`）上，由于整体运行时间极短（小于1秒），MassFlow 的线程池初始化开销和 Numba JIT 的初次编译开销占比相对明显。随着数据量的增加，Numba JIT 并行编译生成的机器码纯计算优势和多线程管线并行优势开始完全释放，使得整体加速比随数据规模增大呈明显的稳步上升趋势。
2. **底层计算模式与设计优化剖析**：
   - **MassFlow (PreprocessorAB)**：采用了多线程分批 flat 数据读取方案，读取与核心计算并行重叠（Overlap）。预处理计算（如平滑与归一化）全部在底层通过 Numba JIT 进行极速并行计算，彻底规避了 Python 的多线程 GIL 限制和单线程 CPU 瓶颈。
   - **pyM2aia**：尽管其核心库基于高效的 C++ 实现，但在 Python 绑定的 `SpectrumIterator` 遍历并消费数据的过程中，需要针对每个光谱在 C++ 和 Python 之间进行转换（如通过 `np.asarray` 将 C++ 内存转换为 Python 的 ndarray）。频繁的交互和单线程 Python 迭代循环造成了严重的 I/O 和计算等待，限制了其在实际 Python 应用中的执行效率。
